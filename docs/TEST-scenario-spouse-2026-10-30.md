# 배우자 테스트 시나리오 체크리스트 (1단계 · 2026-10-30)

기획안 1-4 "배우자 테스트": 설명 없이 앱만 건네고, 아래 흐름을 혼자 끝까지 가는지 본다. 막힌 곳은 **어디서·무슨 말이 보였는지**만 적는다. 한 사람당 15분.

## 준비
- [ ] Expo Go 로 앱을 열고 **첫 실행 상태**(온보딩이 보여야 함). 이미 지난 상태면 앱 데이터 삭제 후 다시.
- [ ] 테스터에게 말할 것은 한 문장뿐: "이 앱으로 오늘 돈 되는 일 하나만 해 보세요."

## 시나리오 A · 첫 실행 → 체험단 응모 (핵심)
| # | 테스터가 해야 하는 일 | 통과 기준 | 결과 |
|---|---|---|---|
| A1 | 온보딩에서 목적 하나 고르기 | 30초 안에 고르고 홈 도착. 건너뛰기를 눌러도 체험단 홈 | |
| A2 | 홈 상단 「돈 되는 일」 카드 3장 읽기 | "뭘 하면 돈이 되는지" 한 문장으로 말할 수 있다 | |
| A3 | 하단 탭으로 **지원금 · 주식 · 커뮤니티 · 마이** 를 오가기 | 탭 이름만 보고 어디인지 안다. 서비스 전환 방법을 묻지 않는다 | |
| A4 | 체험단 탭에서 모집 중 체험 하나 열기 | 상단 세그먼트(홈·탐색·내 응모)로 탐색까지 간다 | |
| A5 | 응모하기 3단계 끝내기 | 검증 문구(연락처·동의)에 막히면 스스로 고친다. "응모를 완료했어요" 도착 | |
| A6 | 내 응모에서 방금 응모 확인 | 다음 할 일 문구("n.j 선정 발표 예정")를 읽고 이해한다 | |

## 시나리오 B · 선정 → 후기 제출 → 지갑
| # | 할 일 | 통과 기준 | 결과 |
|---|---|---|---|
| B1 | 내 응모 → 선정된 체험(코지홈) 열기 | 미션 카드(글자 수·키워드·해시태그·기한)를 읽고 "무엇을 써야 하는지" 말한다 | |
| B2 | 후기 제출하기 → 앱에서 작성 | 실시간 체크리스트가 바뀌는 것을 알아챈다 | |
| B3 | 기준 미달로 제출 시도 | 결과 시트("사진 2장 더 필요해요" 식)를 읽고 수정 또는 그대로 제출을 고른다 | |
| B4 | 응모 내역에서 "검토용 데모 · 승인 받기" | 승인 뒤 **마이 탭 → 오늘 번 돈** 이 +1,000원 된 걸 찾는다 | |
| B5 | 나의 지갑 열기 | 잔액·받은 제품 가치·출금 안내("12월 1일 오픈")를 구분해 설명한다 | |

## 시나리오 C · 지원금
| # | 할 일 | 통과 기준 | 결과 |
|---|---|---|---|
| C1 | 홈 「내 지역 지원금」 카드 누르기 | 지원금 정보 목록으로 간다 (1단계는 자리 화면) | |
| C2 | 마이 → 저장한 정보 | 개수가 맞고 눌러서 이동한다 | |

## 기록할 것
- 막힌 지점 (화면 이름 + 보인 문구)
- 모르겠다고 한 단어 (예: "세그먼트", "리워드", "보완 요청")
- "이건 왜 있어요?" 라고 물은 요소
- 끝난 뒤 한 줄: "이 앱으로 오늘 돈 되는 일은 ___ 이다"

## 알려진 제약 (테스트 전 안내 금지, 기록용)
- 로그인 없음 · 서연맘 계정 고정 · 금액은 데모
- 기한 알림은 개발 빌드에서만 (Expo Go 에서는 안 울림)
- 사진 업로드 없음(장수만), 커뮤니티·매매일지는 자리 화면
