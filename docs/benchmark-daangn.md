### 1-3. 기술 관찰
- 홈 스크립트 95개가 **전부 www.daangn.com 자체 호스팅** — 서드파티 스크립트 태그 없음(분석 도구도 번들에 포함).
- 로컬스토리지 키: PostHog(제품 분석), TikTok 픽셀 세션, Google Ads `_gcl_ls`, `lastExternalReferrer`(유입 추적), `@daangn/maps/map-style-cache`.
- 관찰 창(2.5~3초) 안에서 **추가 네트워크 요청 0건** → 공개 페이지는 서버 렌더링된 정적 결과를 그대로 보여주고, 상호작용 전에는 API를 부르지 않는다. 비공개 API 구조는 관찰하지 않았다(범위 밖).
- 지역 기본값은 IP/최근 위치 기반으로 "제주시 노형동"이 자동 선택됐고, 모든 섹션 헤딩이 동네명으로 시작한다. 지역이 모든 콘텐츠의 1차 키.

## 2. 주부테크에 옮길 패턴 (우선순위)

1. **지역이 1차 키** — 동네생활·알바·업체·거래 모두 "{동네} 검색 결과"로 시작하고 "지역 선택 / 현재 위치로 설정"이 모든 섹션 상단에 반복된다. 주부테크는 지원금(지자체)·체험단(매장)·공구가 지역 의존이므로 **시·구 단위 지역 선택기를 상단바에 상시 배치**하고, 프로필 지역을 `region_code`로 구조화한다.
2. **인기 검색어 칩 블록** — 검색창 아래 6개 칩 + 더보기. 돈되는정보 상단에 "지금 뜨는 지원금" 칩(아이돌봄·교통비·다자녀…)으로 이식하면 탐색 비용이 크게 준다.
3. **랭킹형 홈 리스트** — 홈은 피드가 아니라 "지금 뜨는 동네 이야기" 상위 5개 랭킹. 주부테크 홈도 "이번 주 수익 인증 TOP 5" 또는 "마감 임박 지원금 TOP 5"처럼 **번호 랭킹**으로 압축하면 홈이 가벼워진다.
4. **알바 카드 = 부업 카드의 모델** — 임금 형태(시급/월급/건당)·요일·시간·동네·후기 배지·관심 등록 하트. 주부테크 "부업" 게시판을 자유 글이 아니라 **구조화된 일거리 카드**(보상 형태·소요 시간·지역·후기)로 전환할 근거.
5. **업체 카드 = 광고주 프로필의 모델** — 평점·후기 수·단골 수·소개 한 줄. 체험단 캠페인 상세의 광고주 블록에 **캠페인 횟수·선정률·회원 후기 평점**을 같은 자리에 두면 신뢰 판단이 빨라진다.
6. **상태 배지는 카드 맨 앞** — 거래완료/예약중이 제목보다 앞. 체험단 카드의 모집중/마감/선정완료도 썸네일 위 왼쪽 상단 고정(현재 피그마와 동일, 유지).
7. **공개 페이지에도 로그인 CTA 상시** — 알바는 비로그인 상태에서 "로그인" 버튼을 헤더에 둔다. 주부테크 앱도 둘러보기 모드에서 상단에 "로그인" 1개만 노출하고, 응모·작성 시점에 로그인을 요구한다.

## 3. 당근과 달라야 할 점
- 당근 홈은 "서비스 허브 + 동네 이야기"지만 주부테크 홈은 **오늘 할 수 있는 돈 되는 행동**(미션·마감 지원금·모집 캠페인)이 먼저여야 한다.
- 당근은 동네(읍·면·동)까지 노출한다. 주부테크의 수익 인증·매매일지는 **시 단위**까지만 노출하고 닉네임 기반을 유지한다.
- 당근 알바·업체는 개별 서브도메인/제품으로 분리돼 있다. 주부테크는 초기에는 **한 앱 안의 탭**으로 유지하고, 광고주 쪽(캠페인 등록·검수)만 웹 관리자 센터로 분리한다(현재 구조와 일치).

## 5. 한계와 다음 단계
- 공개 웹만 관찰했으므로 앱 전용 흐름(동네 인증 GPS, 채팅, 당근페이, 키워드 알림 설정 UI)은 근거가 없다. 다음 단계는 에뮬레이터에 당근 앱을 설치해 **디컴파일 없이** 공개 기능만 화면 캡처로 관찰하는 것(REA `capture-adb-screen`).
- REA 번들 정적 분석(`analyze-web-bundle`)은 홈 번들 크기 때문에 4GB 메모리에서 실패했다. 필요하면 `--observation-ms`를 줄이고 섹션 페이지로 재시도.
